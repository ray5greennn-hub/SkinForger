# legacy —— 重写之前的那套工具链

这里面的东西**不参与任何构建**，留着只是为了记录「2026-11-17 之前 SkinForger 是怎么做出来的」。

## 怎么回事

2026-11-17 之前，`SkinForger.Melon.dll`（Main）没有可编译的源码：
每加一个功能，就用 [Mono.Cecil](https://github.com/jbevain/cecil) 对上一版 DLL 做一次 IL 手术 ——
改方法名、注入调用、改字符串常量、把新写的运行时类型整个搬进去。
`cecil-toolchain/` 里就是这些手术刀，每一把都把输入 DLL 的 SHA256 写死在代码里，
只接受那一个确切的输入。

2026-11-17 起 Main 改为自有源码（见 `docs/为什么重写了Main.md`），
这套工具链随之全部退役：它们要加工的那个 DLL 已经不存在了。

## 为什么还留着

* 这是「为什么要重写」最直接的证据：一条二进制补丁链无法满足 GPL 的「对应源码」义务；
* Cecil 的具体用法本身有参考价值 —— 怎么在 IL 里注入一次调用、怎么把一个类型连同它的方法体
  搬进另一个 assembly、怎么在加工前后用哈希把输入输出钉死；
* 当年那些运行时功能（FPS 上限、加载图、动画幅度、改过的图自动留底）就是靠它编进 Main 的，
  现在这些功能的源码在 `src/<功能>/Runtime/`，由授权 Main 直接编译。

## 注意

* `cecil-toolchain/*/Runtime/` 原本有一份功能源码的副本，**已删除** ——
  那是 2026-11-20 的过期快照，现行源码在 `src/` 下。
* `ReleaseAudit` / `ReleasePackager` / `ReleaseVerify` 审的也是旧的二进制补丁链，同样退役。
* 这里的工具**不要**拿来加工现在的 DLL：哈希对不上，会直接拒绝；就算绕过去也只会得到一个坏文件。
